### v0.2에서 바뀐 것
- 기계 안 물건: 편지 봉투 → **동그란 캡슐(공)**. 레퍼런스처럼 공이 가득 찬 기계에서 하나를 집고, **캡슐을 열면 안에 질문 쪽지가 들어 있는** 흐름.
- 방향: **레퍼런스(기아 Lucky Grab)와 같은 구조와 손맛**으로 만든다 (3D 유리 기계, 물리로 굴러가는 공, 가로 폰 패드). 바꾸는 것은 **색·글꼴·캐릭터·말투** — 앱 느낌만 입힌다.
- v0.1에서 만든 2D/3D 시안은 **폐기**. 이 저장소(eq-grab)에서 처음부터 만든다.
- 실시간 연결: 레퍼런스 구조를 그대로 따르기 쉽도록 **Firebase Realtime Database**로 바꿈 (6장).

## 1. 한 줄 요약

전시장 큰 화면에 **동그란 캡슐이 가득 든 뽑기 기계**를 띄운다. 관람객은 **QR을 찍어 자기 폰을 게임 패드로 쓰고**, 캡슐 하나를 집어 열면 **"오늘 저녁 가족에게 물어볼 질문"** 쪽지가 나온다. 질문 카드는 저장·공유할 수 있고, 앱 설치로 이어진다.

## 2. 배경

- 응답하라는 "가족에게 매일 질문 하나를 보내고, 모두 답해야 서로의 답이 열리는 앱"이다. 전시 부스에서 앱 화면만 보여 주면 이 경험이 잘 전해지지 않는다.
- 레퍼런스: **기아 Lucky Grab**(아이엠파인 제작, 2024 부산·2025 서울 모빌리티쇼). 6×3m LED 화면에 공이 가득 찬 가챠 기계를 띄우고, QR로 폰을 컨트롤러로 썼다. 앱 설치 없이 최대 3~4명이 동시에 했고, 집은 공 색깔에 따라 경품이 갈렸다. 후속작 Lucky Pinball(2026)은 스스로 "가족이 즐기는 전시물"이라고 소개했다.
- GitHub의 비공식 재현판(Three.js + Rapier + Firebase)을 로컬에서 실행해 봤다. **웹만으로 같은 경험을 만들 수 있다.** 다만 코드와 에셋은 가져오지 않는다 (라이선스 없음).
- 자세한 조사 내용은 [기획.md](기획.md)에 있다.

## 3. 목표와 지표

| 목표 | 지표 | 목표치 (안) |
| --- | --- | --- |
| 부스로 사람을 모은다 | 판 수 / QR 스캔 수 | 스캔한 사람의 70% 이상이 실제로 플레이 |
| 앱의 핵심("매일 질문 하나")을 몸으로 느끼게 한다 | 질문 카드 저장·공유 비율 | 30% 이상 |
| 앱으로 이어진다 | `utm_source=exhibit` 로 들어온 설치·가족 만들기 | 플레이한 가족의 10% 이상 |
| 줄이 막히지 않는다 | 한 판 걸리는 시간 / 평균 대기 | 1판 40초 이내 (시간당 약 80가족) |

**하지 않는 것(v1)**: 경품 추첨(당첨/꽝), 회원가입·로그인, 이름 등 개인정보 저장, 2인 이상 동시 플레이(→ v2).

## 4. 사용자와 상황

- **주 사용자**: 전시장을 함께 돌아다니는 가족(부모 + 아이, 3세대 포함). 한 명이 조작하고, 나머지는 화면 앞에서 구경하고 응원한다.
- **구경꾼**: 줄 서 있거나 지나가는 사람. 큰 화면만 본다. 캡슐이 열리고 질문이 크게 뜨면 같이 읽는다.
- **진행자**: 부스 스태프 1명. 줄 정리, 문제가 생겼을 때 대신 조작.

### 대표 시나리오
1. 아이가 큰 화면 속 알록달록한 캡슐 기계를 보고 멈춘다. 부모가 화면 구석의 QR을 찍는다.
2. 폰이 열리고 "누구네 가족이에요?" → "지민이네" 입력 → 대기 2번째.
3. 차례가 오면 폰이 진동하고 큰 화면에 "지민이네 가족 차례!" 3·2·1.
4. 아이가 폰을 가로로 들고 십자키로 **하늘색 캡슐(마음 질문)** 위로 옮긴 뒤 GRAB.
5. 집게가 캡슐을 물고 출구로 → 두구두구 → **캡슐이 화면 가운데로 굴러와 딸깍 열리고**, 안에서 말린 쪽지가 펴지며 질문이 크게: *"들은 말 중에 오래 기억에 남은 다정한 말은?"*
6. 폰에서도 같은 캡슐이 열리며 질문 카드가 뜬다. [카드 저장] [가족 단톡방에 보내기] [앱에서 매일 받기].
7. 가족은 부스를 떠나며 질문 얘기를 하고, 저녁 식탁에서 다시 꺼낸다.

### 5-4. 게임 규칙

- 한 판 = 한 가족 = 조작 20초 + 기회 최대 2번.
- 집기는 **조금만 맞추면 잡힌다**. 집게 중심에서 일정 거리 안의 캡슐 중 가장 위의 것을 잡는다. 물리 결과보다 "잡힘"을 우선하고, 집은 뒤 떨어뜨리는 연출은 없다.
- **캡슐 색 = 질문 주제**. 결과 질문은 집은 캡슐 색의 주제 안에서 고른다. 같은 날 같은 질문은 되도록 다시 안 나오게 한다(주제별 덱을 섞어 순서대로).

| 캡슐 (아래 반쪽 색, 위 반쪽은 반투명) | 주제 | 비율 |
| --- | --- | --- |
| 살구 `#EBA88F` | 추억 · 어린 시절 | 25% |
| 노랑 `#F6CF6E` | 일상 · 음식 | 25% |
| 하늘 `#A9CBE3` | 마음 · 고마움 | 25% |
| 연두 `#97B488` | 재미 · 갈림길 | 22% |
| 금색 | 특별한 질문 (+기념품) | 3% |

### 5-5. 질문 데이터

- 재료: `자료/새 질문2.xlsx` (+ 예비 질문).
- **뺄 것**: 짝 질문, 가족 퀴즈, 누구 답이게, 텔레파시, 이름 투표처럼 앱 기능에 기대는 종류. 사진·목소리 답, 날짜·기념일 질문, "편지 친구", "이번 주", "오늘 편지"처럼 앱 안 상황을 아는 문장.
- **남길 것**: 식탁에서 말로 바로 답할 수 있는 모두 질문과 갈림길.
- 수량: 주제별 12개 × 4 + 특별 6개 ≈ 54개. `question-reviewer` 에이전트로 한 번 더 검수한다.
- 형식: `questions.json` → `{ id, topic, text, choices? }`

## 6. 앱 느낌 입히기 (레퍼런스와 다른 점은 여기만)

| 레퍼런스 | 응답하라 판 |
| --- | --- |
| 콘크리트 벽, 형광 공, 네온·블룸 | 따뜻한 방 벽지, **파스텔 4색 + 금색 캡슐**, 은은한 조명 |
| 산업적인 사각 기계 | 지붕이 있는 **집 모양 기계**(앱의 "우리 집" 세계관), 나무·크림 재질 |
| 영어 디스플레이 글꼴 (WINNER 등) | **Pretendard + Gaegu**, 다정한 반말 ("우리 가족 차례!") |
| 결과 = 당첨/꽝 | 결과 = **질문 쪽지**. 꽝 없음 |
| 캐릭터 없음 | **편지 친구(비둘기·강아지·고양이)** 가 기계 위를 돌아다니고, 빈손이면 캡슐을 굴려 줌 |
| 효과음 위주 | 효과음 + 캡슐 열릴 때 "딸깍", 쪽지 펴질 때 종이 소리 |

색·글꼴은 `app/design_ref/v0.11/Kit_Colors.html`, 캐릭터는 `Kit_Messenger.html`을 따른다.

## 7. 기술 요구사항

### 저장소
- 앱 저장소와 **분리된 새 저장소**에서 만든다 (이름은 10장).
- 정적 웹만: `screen.html`(큰 화면) · `play.html`(폰) · `admin.html`(진행자) · `questions.json` · `assets/`. 빌드 도구 없이 시작하고, 필요해지면 Vite.

### 구조 (레퍼런스와 같은 방식)
- **큰 화면 PC가 게임 상태의 주인**. 폰은 입력만 보내고 상태를 따라 그린다.
- 그래픽: **Three.js**(3D 유리 기계). 물리: **Rapier 3D**(캡슐이 쌓이고 굴러감).
- 실시간 연결: **Firebase Realtime Database** — 앱이 이미 쓰는 Firebase 프로젝트(`eungdap-770f5`)에 RTDB를 켜고 `grab/{room}/` 아래에 둔다.
  - `state`(단계·남은 시간) · `queue`(대기열, `runTransaction`) · `input/{slot}`(`{dx, dz, grab}` — 바뀔 때만, 초당 최대 15번) · `result/{slot}` · `plays`(통계)
  - 폰이 끊기면 `onDisconnect`로 자리 정리.
  - 좌표가 아니라 "누르는 동안 이동" 입력을 보내므로 지연이 있어도 안전하다.
- 배포: 같은 Firebase 프로젝트에 **Hosting 사이트를 하나 더** (예: `eungdap-grab.web.app`). 앱 배포와 섞이지 않는다.
- 보안 규칙: `grab/` 아래만 읽기·쓰기 허용, 값 크기·형식 검사. 이름은 당일 삭제.

### 비기능
| 항목 | 요구 |
| --- | --- |
| 성능 | 큰 화면 60fps (전시 PC 기준, 그래픽 카드 권장), 폰 첫 화면 2초 안 (LTE) |
| 현장 네트워크 | 큰 화면 PC는 유선. 인터넷이 끊겨도 진행자가 키보드/USB 게임패드로 계속 진행 (질문은 로컬 파일) |
| 이탈 | 폰이 10초 넘게 끊기면 자동 GRAB → 결과는 큰 화면에만 → 다음 가족 |
| 화면 | 가로 16:9 기준, 세로 9:16도 지원 (현장 화면 방향 미정) |
| 접근성 | 버튼 최소 64px, 어르신·아이 기준 큰 글씨, 소리 없이도 이해되는 연출 |
| 저작권 | 레퍼런스·재현판의 코드·이미지·소리는 쓰지 않는다 |

## 8. 필요한 에셋 — Google Flow로 만들기

**필요한 그래픽 요소는 Chrome에서 Google Flow(labs.google/flow)로 만들면 된다.** Flow는 이미지(Imagen / Nano Banana)와 짧은 영상(Veo)을 만든다. 앱 디자인 키트 화면을 **참고 이미지(ingredients)** 로 넣어 톤을 맞춘다.

### 만드는 순서
1. 참고 이미지 준비: `app/design_ref/v0.11/Kit_Messenger.html`, `Kit_Houses.html`, `Kit_Colors.html` 화면 캡처.
2. Flow에서 생성 → 마음에 드는 것만 다운로드.
3. 투명 배경이 필요한 요소는 배경 제거.
4. 새 저장소 `assets/`에 `요소이름_버전.png|webp|jpg`로 넣는다. 3D에서는 텍스처·배경·UI로 쓴다.

### 공통 스타일 프롬프트 (모든 요청 앞에 붙임)
> Soft hand-drawn children's picture-book style, warm and cozy, muted pastel palette (apricot #EBA88F, butter yellow #F6CF6E, sky blue #A9CBE3, sage green #97B488, soft gold), soft brown outlines (#A08E7D), gentle grain, no text.
