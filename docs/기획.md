# 전시용 서브 프로젝트 기획 — 「오늘의 질문 뽑기」 (가제)

> 큰 화면에 인형뽑기 기계를 띄우고, 관람객이 QR로 들어와 자기 폰을 조이스틱으로 써서 **편지 하나를 집으면, 그 안에 오늘 저녁 가족과 나눌 질문이 들어 있는** 체험.
> 앱 소개 부스 옆에 두는 "직접 해 보는" 전시물이다.

작성 2026-11-27 · 상태: 초안 (아래 "정해야 할 것" 확인 필요)

---

## 1. 자료조사

### 1-1. 레퍼런스: 기아 Lucky Grab (아이엠파인 제작)

**원작은 기아 전시 부스의 경품 게임**이고, 만든 곳은 인터랙티브 개발사 **아이엠파인(I M fine, @imfine.interactive)** 이다. 대행사는 이노션.

| | 2024 부산모빌리티쇼 (2024.6) | 2025 서울모빌리티쇼 (2025.4, 킨텍스) |
| --- | --- | --- |
| 화면 | 가로 6m × 세로 3m LED | 3m × 6m LED |
| 입장 | **앱 설치·가입 없이 QR 스캔** → 내 폰이 컨트롤러 | 같음 |
| 동시 인원 | 최대 3명 | 최대 4명 |
| 누가 하나 | 기아관 **스탬프 투어를 끝낸 사람**만 (Lucky Grab Giveaway 존) | 같음 |
| 보상 | **집은 공의 색깔에 따라 다른 경품** | 플레이모빌 협업 굿즈 |
| 연출 | LED 빛 효과로 멀리서도 눈에 띔 | 기아 × 플레이모빌 브랜드 콘텐츠로 꾸밈 |

- **기술**: 아이엠파인의 자체 플랫폼 **Joy Stream** 위에서 만듦. 회사 소개로는 "클라우드 스트리밍 기반으로 모바일과 대형 디스플레이를 잇는" 솔루션. KOCCA 등록 정보로는 5G 클라우드로 DOOH(옥외광고) 캠페인용 경험을 만드는 플랫폼. 채용 공고상 Unity로 인터랙티브 콘텐츠를 개발하는 회사 → **게임은 서버/PC(Unity)에서 돌고, 폰은 입력만 보내는 구조**로 보인다 (공개 자료에 내부 구조 설명은 없음, 추정).
- **폰 컨트롤러**(인스타그램 이미지): 폰을 **가로로 들고** 왼쪽에 십자 방향키(+), 오른쪽에 마름모 모양 **Grab 버튼**. 게임기 패드 같은 모양이고, 결과("밀면 럭키그랩 당첨")는 폰에 표시.
- **이후 시리즈**: 2026 부산모빌리티쇼(2026.7)에서는 같은 구조로 **Lucky Pinball**을 만듦. 4×6m LED + 무선 모바일 컨트롤러 4대, 원하는 힘으로 공을 쏴 경품 칸을 노림. 신호등·차단기·미니카를 장애물로 써서 기아다움을 살렸고, 회사 스스로 **"가족이 즐기는(family-friendly)" 전시물**이라고 소개 → 우리 기획과 가장 가까운 결.
- 롯데면세점 명동 스타에비뉴의 Lucky Picker / Lucky Flip도 같은 회사의 "참여 → 보상 발급 → 운영 관리" 통합 솔루션.

**우리가 가져갈 것**
- 앱 설치 없이 QR 한 번 → 바로 조작. 진입 장벽이 없다.
- 거대한 화면과 빛 연출이 **구경꾼을 모은다**. 하는 사람보다 보는 사람이 많다.
- **색깔 = 결과**. 공 색에 따라 경품이 달라지는 규칙은 우리의 "봉투 색 = 질문 주제"와 그대로 겹친다.
- 폰은 게임 패드 모양(가로, 방향키 + Grab)이라 설명 없이도 다들 안다.
- 원작은 "스탬프 투어 완주자 보상"이라 줄이 관리됐다. 우리는 누구나 할 수 있게 하되 **대기열**이 꼭 필요하다.

**우리와 다른 점**
- 원작의 목적은 **경품 증정**. 우리는 **누구나 질문 하나를 가져가고, 그게 앱 소개로 이어지는 것**이 목적.
- 원작은 LED 벽·이노션·전문 개발사 규모. 우리는 **TV/모니터 한 대 + 웹**으로 같은 경험의 핵심만 가져온다.

### 1-1-b. 참고: GitHub의 lucky-grab (비공식 재현판)

처음 찾은 [yeon51422777-maker/lucky-grab](https://github.com/yeon51422777-maker/lucky-grab)은 **기아 원작이 아니라 개인이 따라 만든 재현판**이다. 콘크리트 벽 배경·은색 공 같은 겉모습을 원작에서 본떴고, Firebase 경로가 다른 개인 프로젝트(편지쓰기) 아래에 있다. 비슷하게 [skillmoph/lucky-grab](https://github.com/skillmoph/lucky-grab)도 "Lucky Grab 행사 설치물에서 영감을 받은 브라우저 재현"이라고 스스로 밝힌다. 원작의 실제 구조와는 다를 수 있지만, **웹만으로 같은 경험을 만드는 방법**의 참고로는 쓸 만하다. 로컬에서 키보드로 실행해 동작을 확인했다.

- 파일 3개로 된 정적 웹: `index.html`(큰 화면) · `play.html`(폰 컨트롤러) · `admin.html`(진행자), 라이선스 표기 없음

| 항목 | 재현판이 하는 방식 |
| --- | --- |
| 그래픽 | Three.js 0.169 3D + Bloom 후처리, 유리 재질 공(캡슐) 더미 |
| 물리 | Rapier 3D (공 충돌·집기) |
| 연결 | Firebase Realtime DB, `rolling/luckygrab/{room}` 아래에 `state` · `players` · `input` · `turn` · `result` · `lottery` · `winners` |
| 입장 | 큰 화면에 QR → 폰에서 이름(8자) 입력 → `runTransaction`으로 빈 자리(P1/P2) 차지, `onDisconnect`로 나가면 자리 반환 |
| 인원 | 1인(세로 9:16) / 2인(가로 16:9, 연두·핑크 크레인 두 대) |
| 조작 | **좌·우 버튼 + GRAB 하나**. 좌우는 누르고 있는 동안 이동, GRAB은 톡=더미 위까지, 꾹=더 깊이. 입력은 `{dir, grab, hold}`를 DB에 씀 |
| 시간 | 한 사람 20초, 기회 1번. 미끄러짐 0 (잡으면 무조건 올라옴) |
| 당첨 | 집는 공의 색과 상관없이 **미리 섞어 둔 제비(deck)** 순서로 당첨/꽝 결정. 진행자가 "참가 인원·선물 수"를 넣으면 deck을 만듦 → 선물 수를 정확히 맞출 수 있음 |
| 결과 | 폰에 WINNER/NICE TRY 화면, 당첨이면 확인코드 + 카카오 오픈채팅 버튼(문구 복사) |
| 그 밖에 | 대기 화면 배경음악·효과음(Web Audio로 직접 합성), 카운트다운, 진동, 화면 꺼짐 방지(Wake Lock) |

**재현판에서 가져올 점**
- 큰 화면이 "주인", 폰은 입력만 보내는 얇은 컨트롤러 → 폰 쪽 개발이 가볍다.
- 집기 성공 여부를 물리에 맡기지 않고 **결과를 미리 정해 두는** 구조 (전시에서는 "못 잡아서 아무것도 없음"이 제일 나쁜 경험).
- 대기·카운트다운·결과를 폰과 큰 화면에 동시에 보여 주는 연출.

**재현판과 다른 점**
- 재현판은 미리 섞은 제비로 **당첨/꽝**을 정한다 (원작은 공 색깔로 경품이 갈림). 우리는 **누구나 질문 하나를 가져간다**. 꽝이 없다.
- 결과가 "확인코드"가 아니라 **질문 카드**이고, 그 카드가 앱으로 이어지는 입구가 된다.
- 라이선스가 없는 저장소라 **코드는 복사하지 않고 구조만 참고**해서 새로 만든다.

### 1-3. 기술 조사 요약

- **실시간 연결**: Supabase Realtime Broadcast 기준 1KB 메시지 지연 중앙값 58ms · p95 279ms (Supabase 자체 벤치마크). 무료 플랜 초당 100메시지, Pro 500. 한 명이 조작하는 구조라 입력을 초당 20번 이하로 보내면 여유 있음. 다만 p95가 300ms 가까이라 **"누르는 동안 이동"** 방식(재현판과 같음)이 좌표를 실시간으로 쏘는 방식보다 끊김에 강하다.
- **Presence(접속자 목록)** 는 메시지 한도의 10%라 대기열에는 Presence 대신 DB 행 + Broadcast를 쓴다.
- 전시장 와이파이는 믿지 않는다: 큰 화면 PC는 유선, 관람객 폰은 LTE/5G로 붙는다고 가정.

## 2. 컨셉

### 한 줄
**"편지 친구가 가득 든 뽑기 기계에서 편지 하나를 집으면, 오늘 저녁 가족에게 물어볼 질문이 나와요."**

### 앱과 이어지는 이유
- 앱의 핵심은 "매일 질문 하나". 전시에서는 그 "질문 하나"를 **손으로 직접 뽑는 경험**으로 바꿔 보여 준다.
- 기계 안에 든 것은 인형이 아니라 앱 세계관의 **편지 봉투 · 편지 친구 · 작은 집** 소품. 디자인 키트(`app/design_ref/v0.11/Kit_*`)의 색과 일러스트를 그대로 쓴다.
- 결과 카드에 "이 질문, 앱에서 가족 모두 답하면 서로의 답이 열려요"를 붙여 **앱 구조를 한 번에 설명**한다.

### 경험 흐름

```
[큰 화면 대기 루프]  편지들이 기계 안에서 살랑살랑 · "QR을 찍고 질문을 뽑아 보세요"
      │ QR 스캔 (앱 설치 없음, 웹)
[폰: 입장]  "누구랑 왔어요?" 가족 이름/별명 (선택) → 대기열 번호 · 예상 대기 시간
      │ 내 차례
[큰 화면 + 폰: 3·2·1]  큰 화면에 "○○네 가족 차례!"
[폰: 조이스틱 20초]  편지 위로 이동 → 꾹 눌러 집기
      │ 집은 편지가 출구로
[큰 화면] 봉투가 열리며 질문이 크게 나옴 (구경하는 사람도 같이 읽음)
[폰: 질문 카드]  질문 + "오늘 저녁 식탁에서 물어보세요"
                 [카드 저장] [가족에게 보내기(카톡 공유)] [앱에서 이어서 하기]
```

### 꽝 없는 규칙
- 집게가 빈손으로 올라오면 **한 번 더**(최대 2회). 2번째도 놓치면 편지 친구가 "내가 하나 골라 줄게!" 하며 하나를 건네줌 → 누구나 질문을 가져간다.
- 난이도는 "조금만 맞추면 잡힌다" 수준. 재미는 **어떤 질문이 나올지**에서 나오게 한다.

### 편지 색 = 질문 주제 (선택하는 재미)
기계 안 봉투 색으로 주제를 나눠, 가족이 "우리는 추억 질문 뽑자!" 하고 **노리는 재미**를 준다.

| 봉투 | 주제 (`새 질문2` 카테고리 기준) | 결 |
| --- | --- | --- |
| 살구 | 추억 · 어린 시절 | 이야기가 길어지는 질문 |
| 노랑 | 음식 · 입맛 / 일상 · 오늘 | 가볍게 시작 |
| 하늘 | 마음 · 감정 | 조금 깊은 질문 |
| 연두 | 취향 · 재미 / 갈림길 | 웃음 나는 고르기 |
| 금색 (드묾) | 특별한 질문 | 뽑으면 큰 화면 연출 + 작은 기념품(스티커 등, 있으면) |

## 3. 질문 고르기

- 재료: `자료/새 질문2.xlsx`의 365개 + `예비 질문` 104개.
- **전시용으로 맞지 않는 것 빼기**
  - 짝 질문 · 가족 퀴즈 · 누구 답이게 · 텔레파시 · 이름 투표: 앱 기능(답이 열림, 주인공 지정 등)에 기대는 종류라 제외
  - 사진·목소리로 답하는 질문, 날짜가 붙은 질문(기념일·특별한 날), "편지 친구가 궁금해해" 같은 앱 안 설정을 아는 문장
- **남길 것**: "모두 질문"과 "갈림길" 가운데 **식탁에서 말로 바로 답할 수 있는** 문장. 갈림길은 선택지를 카드에 같이 적는다 (예: "평생 하나만 먹어야 한다면? 밥 / 면 / 빵").
- 목표 수량: 주제별 12개 × 4 + 특별 6개 ≈ **54개**. 하루 관람객이 수백 명이어도 같은 가족이 같은 질문을 받지 않을 정도면 충분.
- 고른 뒤 `.claude/agents/question-reviewer.md` 기준(모든 세대·가족 구성에서 곤란하지 않은가)으로 한 번 더 검수. 전시장은 **처음 보는 가족 구성**이 많으므로 이 기준이 앱보다 더 중요.
- 결과 파일: `전시_질문뽑기/전시_질문.csv` (번호, 주제, 봉투색, 질문, 선택지)

## 4. 화면 구성

### 큰 화면 (전시장 TV/LED, 가로 16:9 기준)
| 상태 | 보여 줄 것 |
| --- | --- |
| 대기 | 기계 + 살랑이는 편지들, 큰 QR, "지금 대기 n가족", 방금 뽑힌 질문이 아래에 흘러감(티커) |
| 카운트다운 | "○○네 가족 차례!" 3·2·1 |
| 조작 중 | 크레인 이동, 남은 시간 원형 게이지, 구경꾼용 효과음 |
| 결과 | 봉투가 열리며 질문이 화면 가득 → 4초 뒤 대기로 |

- 2인 동시(크레인 두 대)는 **2차**. 가족 단위 관람이라 "한 가족 = 한 판"이 더 자연스럽다.

### 폰 (세로, 웹)
1. **입장**: 가족 이름(선택, 8자) · 개인정보 동의 없음(아무것도 저장 안 함 문구)
2. **대기**: 내 번호 · 앞에 n가족 · 기다리는 동안 "봉투 색 미리 보기"
3. **조이스틱**: 아래 "조작" 참고
4. **질문 카드**: 카드 이미지 저장 · 카카오 공유 · 앱 설치/열기 버튼 · "한 번 더 줄 서기"

### 조작 (정해야 할 것 ①)
| 안 | 방식 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 좌우 + 집기 (GitHub 재현판과 같음) | ◀ ▶ 누르는 동안 이동, 큰 버튼 꾹=집기 | 제일 쉬움, 지연에 강함, 어르신·아이도 바로 | 노리는 재미가 약함 |
| **B. 십자 방향키 + Grab (기아 원작과 같음, 추천)** | 폰을 가로로 들고 왼손 십자키로 앞뒤·좌우, 오른손 큰 Grab 버튼. 원형 가상 스틱도 같은 입력으로 바꿔 끼울 수 있음 | "인형뽑기 하는 느낌"이 제대로 남, 봉투 색을 노릴 수 있음 | 3D 화면에서 앞뒤 거리감이 어려움 → 바닥에 크레인 그림자 + 위에서 본 미니맵으로 보완 |
| C. 진짜 기계처럼 2단계 | 1단계 좌우 버튼 → 2단계 앞뒤 버튼 → 자동 하강 | 실물 인형뽑기와 똑같음 | 시간이 더 걸려 회전율이 떨어짐 |

추천은 B. 입력은 좌표가 아니라 **방향(x, z ∈ -1~1)을 초당 최대 15번, 바뀔 때만** 보낸다.

## 5. 기술 설계

### 구성
```
전시_질문뽑기/
  web/
    screen.html   큰 화면 (Three.js + Rapier, 이 PC가 게임 상태의 주인)
    play.html     폰 컨트롤러 (가벼운 HTML/JS)
    admin.html    진행자: 대기열 정리, 질문 목록 확인, 통계, 강제 다음 차례
    questions.json
  기획.md (이 파일)
```
- Flutter 앱과 **완전히 분리된 정적 웹**. 배포는 기존 Firebase 프로젝트(`eungdap-770f5`)에 **Hosting 사이트를 하나 더** 만들어 올림 (예: `eungdap-grab.web.app`). 앱 배포에 영향 없음.

### 실시간 연결: Supabase Realtime (추천) vs Firebase RTDB
| | Supabase Realtime (`eungdap2`) | Firebase RTDB |
| --- | --- | --- |
| 이미 쓰는가 | 앱 서버 전체가 여기 | Firebase는 Hosting·알림만 씀 (RTDB는 새로 켜야 함) |
| 입력 전달 | Broadcast 채널 (DB에 안 남음) | DB 경로에 set |
| 대기열 | `exhibit_queue` 테이블 + RLS | `runTransaction` |
| 통계 | 같은 DB에 바로 쌓임 → SQL로 집계 | 따로 내보내야 함 |
| 검증된 사례 | — | GitHub 재현판이 이 방식 |

→ **Supabase Realtime 추천.** 팀이 이미 키·권한·마이그레이션 방식을 갖고 있고, 전시 통계를 앱 데이터와 같은 곳에서 볼 수 있다. 큰 화면 PC 한 대가 상태의 주인이라 서버 함수는 거의 필요 없다.
- 새 마이그레이션 하나: `exhibit_plays`(뽑은 시각, 질문 번호, 봉투 색, 공유/앱 버튼 눌렀는지) · 대기열용 테이블. 이름은 저장하지 않거나 하루 뒤 지움.

### 그래픽: 3D vs 2D (정해야 할 것 ②)
- **3D (Three.js + Rapier, 추천)**: 레퍼런스처럼 유리 기계 안 물건이 쌓이고 흔들리는 "진짜 같은" 맛. 봉투는 납작한 상자 + 브랜드 일러스트 텍스처, 재질은 번쩍이는 네온 대신 **따뜻한 종이·나무 톤**(앱 팔레트 `#3D3833` `#C9654C` `#FFFDF6`, 글씨 Gaegu/Pretendard).
- 2D (Canvas + Matter.js, 옆에서 본 모습): 기존 SVG를 그대로 써서 빠르고 브랜드와 딱 맞지만, 조이스틱 앞뒤 이동(B안)이 의미 없어짐 → A안 조작과 짝.

### 앱으로 이어지기
- 1차: 결과 카드의 "앱에서 이어서 하기" = 스토어/웹 링크 + `utm_source=exhibit`. 카드 이미지를 저장·공유하면 **카드 자체가 홍보물**.
- 2차(앱 수정 필요): 링크에 `?q=전시질문번호`를 붙여, 새로 가족을 만든 사람의 **첫 질문을 그때 뽑은 질문으로** 보내 줌. 경험이 그대로 이어지지만 앱 쪽 작업이 들어가므로 일정 보고 결정.

### 현장 대비
- 큰 화면 PC: 유선 인터넷, 크롬 키오스크 모드, 화면 꺼짐 끔
- 인터넷이 끊기면: 큰 화면 PC에 **USB 게임패드/키보드**로 진행자가 대신 조작할 수 있게 (질문은 `questions.json`이 로컬에 있으니 계속 돌아감)
- 폰이 중간에 꺼지거나 나가면: 10초 안에 안 돌아오면 자동으로 집기 → 결과는 큰 화면에만, 대기열 다음으로
- 같은 폰이 계속 줄 서는 것: 대기열에 한 폰 한 자리
